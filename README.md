# مسار — Masar

**[masar-bh.com](https://masar-bh.com)** — سوقٌ ومنصّة دراسةٍ لشرح المقررات
الجامعية في البحرين، تبدأ بمقررات جامعة البحرين بالعربية.

الطالب يتصفّح الكتالوج علنًا، ويشتري **باقةً** من المقرر (منتصف الفصل، أو
النهائي، أو الدورة الكاملة) لا المقرر كلّه بالضرورة، ثم يدرس داخل المنصّة:
محاضرات، اختبارات، واجبات، درجات، ورسائل مع المدرّب.

مبنية بـ Next.js 15 (App Router) و TypeScript و Tailwind CSS v4، بدعم RTL
كامل، على Neon PostgreSQL و Cloudflare R2.

> **أصل المستودع:** بدأ باسم «منصة مركز حساب» — نظام تعلّمٍ لمركز تدريب،
> انسحب عميله بعد بناء نحو ٨٥٪ من النسخة الأولى. فأُعيد توجيه المستودع
> وقاعدة البيانات والتخزين والاستضافة نفسها إلى «مسار». ولذلك تجد في
> التعليقات مقارناتٍ بين «مركز حساب» و«مسار» — وهي مقصودة: تشرح **لماذا**
> صار القرار على ما هو عليه، لا بقايا لم تُنظَّف.

## التشغيل

### أ) مع Neon (قاعدة بيانات سحابية)

```bash
cp .env.example .env
```

ثم افتح `.env` وعبّئ قيمتين:

- `DATABASE_URL` — رابط Neon **Pooled** (يحوي `-pooler`). يستخدمه
  التطبيق وقت التشغيل.
- `DIRECT_URL` — رابط Neon **Direct** (بلا `-pooler`). تستخدمه الهجرات.
  للتطوير المحلي يمكن وضع نفس الرابط في الاثنين.
- `AUTH_SECRET` — ولّده بـ:
  `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`

ثم:

```bash
npm install        # يشغّل prisma generate تلقائيًا
npm run db:migrate # إنشاء الجداول على Neon
npm run db:seed    # حسابات الإدارة والمدرّب + كليّتان + مقرر ARAB110 بباقاته
npm run dev        # http://localhost:3000 → /login
```

> `npm run db:up` **غير مطلوب** مع Neon — فهو يشغّل PostgreSQL محليًا عبر Docker.

### ب) مع Docker محليًا (بديل)

```bash
cp .env.example .env    # اترك رابط Docker الموجود في التعليقات
npm install
npm run db:up           # يشغّل PostgreSQL في حاوية
npm run db:migrate
npm run db:seed
npm run dev
```

### حسابات البذر

الدخول **بالبريد** لا باسم المستخدم: `admin@masar.bh` و`ustath@masar.bh`.

**وكلمات المرور لم تعد مكتوبةً في المستودع.** يقرأ `prisma/seed.ts` قيمتَي
`SEED_ADMIN_PASSWORD` و`SEED_TEACHER_PASSWORD` من `.env` (لا `.env.local` —
فـPrisma CLI لا يقرؤه)، وإن غابتا **ولّد كلمةً عشوائية لكل حساب وطبعها
مرّةً واحدة** في نهاية البذر. التقط ذلك المخرَج؛ لن يُعرض ثانيةً.

> وإن ضاعت: إعادة `npx prisma db seed` **لا تفيد** — البذر يستعمل
> «ابحث ثمّ أنشئ» فلا يلمس كلمة حسابٍ قائم (وهو مقصود: `upsert` كان
> يطبع كلمةً لا تُطبَّق أبدًا). استعمل `scripts/set-seed-passwords.mts`.

أوامر أخرى:

```bash
npm run build      # بناء الإنتاج
npm run typecheck  # فحص الأنواع
npm run db:studio  # واجهة تصفّح قاعدة البيانات
```

## الهيكل العام والتنقّل

الشريط الجانبي مثبّت يمين الشاشة بعرض 260px من مقاس `lg` فأعلى، وتحته
يتحوّل إلى لوحة منسحبة من اليمين.

قواعد من نظام التصميم مطبّقة في `src/lib/navigation.ts`:

- **ستة عناصر جذرية كحد أقصى** — النشاط، مقرراتي، الدرجات، الرسائل،
  الملف الشخصي، الإعدادات. لا تُضف عنصرًا سابعًا؛ أي وظيفة جديدة تندرج
  تحت أحدها.
- العنصر النشط: خط رأسي + خلفية خفيفة، بلا لون نص صاخب.
- العدّادات تظهر فقط عند وجود عناصر تتطلب إجراءً من المستخدم.
- الأيقونات أحادية اللون بوزن واحد (`lucide-react` بسماكة 1.75).

### الاتجاه: خصائص منطقية فقط

لا يوجد في المشروع أي خاصية اتجاه فيزيائية (`left`, `right`, `ml`, `mr`,
`pl`, `pr`, `border-l`, `border-r`, `text-left`, `text-right`). كل شيء
منطقي، فينقلب التخطيط كاملًا بتغيير `dir` وحده دون لمس أي كلاس:

| الاستخدام | الكلاس | يُنتج | RTL | LTR |
|---|---|---|---|---|
| تثبيت الشريط الجانبي | `start-0` | `inset-inline-start` | يمين | يسار |
| حدّ الشريط | `border-e` | `border-inline-end` | يسار | يمين |
| هامش المحتوى | `lg:ms-[260px]` | `margin-inline-start` | يمين | يسار |
| خط العنصر النشط | `before:end-0` | `inset-inline-end` | يسار | يمين |
| حشوة بند القائمة | `ps-3` / `pe-4` | `padding-inline-*` | — | — |

ترتيب عناصر بند القائمة يعتمد على تدفّق DOM الطبيعي (أيقونة ← نص ← عدّاد)
لا على `order`، فينقلب هو الآخر تلقائيًا: الأيقونة على الجهة الابتدائية
دائمًا (يمين في RTL، يسار في LTR).

لإضافة الإنجليزية لاحقًا يكفي تغيير `lang` و`dir` في `src/app/layout.tsx`
(أو تمريرهما من التوجيه i18n) — لا تعديل على أي مكوّن.

### الشعار — مصدرٌ واحد، وسبعة مُخرَجات

الهوية **ليست ملفًّا واحدًا**: سبعةُ ملفّات، ثلاثةٌ منها لا تُرى إلا على
شاشة هاتفٍ مثبَّتٍ عليه التطبيق. ولذلك تُشتقّ كلّها آليًّا من مصدرٍ واحد
(`assets/logo-source.png`) ولا يُحرَّر أيٌّ منها بيد:

```bash
npx tsx --tsconfig tsconfig.script.json scripts/generate-icons.mts assets/logo-source.png
```

| المُخرَج | المقاس | أين يُرى |
|---|---|---|
| `public/logo-masar.png` | ١٠٢٤، شفّاف | الواجهة كلّها عبر مكوّن `Logo` |
| `public/icon-192/512.png` | تغطية ٧٨٪ | التطبيق المثبَّت + بطاقة واتساب |
| `public/icon-maskable-192/512.png` | تغطية ٥٦٪ | أيقونة أندرويد المقتطعة |
| `public/apple-touch-icon.png` | ١٨٠×١٨٠ | شاشة آيفون الرئيسية |
| `src/app/icon.png` | ٥١٢ | أيقونة التبويب |

السكربت يكتب `assets/brand-lock.json` ببصمة المصدر وبصمة كل مُخرَج،
و`scripts/brand-regression.mts` يعيد حسابها — فيسقط إن بُدِّل ملفٌّ وحده
أو تُرك وحده. **هذا الحارس وُجد لعطلٍ وقع فعلًا:** بُدِّل الشعار في الموقع
وبقي القديم في التطبيق المثبَّت، ولم يمسكه بناءٌ ولا `tsc`.

**و`SITE.brandVersion` تُلحق بكل رابط أصلٍ بصريّ.** النشر وحده لا يُظهر
الشعار الجديد لأحد: المتصفّح يخزّن الملفّ بعنوانه، وواتساب يخزّن
`og:image` لكل رابطٍ شورك، ونظام الهاتف يخزّن أيقونة التطبيق المثبَّت.

### لا بيانات وهمية

كل ما يظهر في الواجهة يأتي من قاعدة البيانات. سجل النشاط يدمج الإعلانات
المنشورة والمحاضرات الجاهزة عبر مقررات المستخدم؛ ولإضافة مصدر جديد
(درجات، واجبات) يكفي دمجه في `getActivityFeed`.

العدّادات التي لا جداول لها بعد (`/grades`, `/messages`) تُرجع صفرًا،
و`CountBadge` لا يعرض شيئًا عند الصفر — فلا شارات كاذبة.

## المنطقة الإدارية

قاعدة التصميم تمنع عنصرًا سابعًا في القائمة الجانبية، لذلك تعيش أدوات
الإدارة **داخل "الإعدادات"** بتبويبات فرعية:

| المسار | الوظيفة |
|---|---|
| `/settings/orders` | مراجعة الطلبات: تأكيد الدفع، الإلغاء، الاسترجاع |
| `/settings/courses` | إنشاء المقررات والباقات وإسناد المدرّبين |
| `/settings/courses/[id]` | الدروس، الباقات، الأسعار، النشر |
| `/settings/faculties` | الكليّات التي تُجمَع تحتها المقررات |
| `/settings/students` | الطلاب ومنح الوصول يدويًا |
| `/settings/instructors` | المدرّبون |
| `/settings/users` | إنشاء الحسابات، الأدوار، التعطيل والتفعيل |

`/settings` يحوّل الإدارة تلقائيًا إلى أول تبويب، ويعرض لغيرهم صفحة
التفضيلات العادية.

**الستّة تعيش داخل مجموعة `(tabs)`** التي يحمل تخطيطُها `AppPage` وشريط
التبويبات، فلا يختفي الشريط مع كل تنقّلة. صفحةٌ جديدة هناك تُعيد جزءًا
مجرّدًا (`fragment`) لا `AppPage` — وإلّا ازدوج الغلاف. يحرس ذلك
`scripts/nav-feedback-regression.mts`.

### كلمات المرور

الإدارة تنشئ الحساب بكلمة مرور مبدئية، ويُفعَّل `mustChangePassword`
تلقائيًا. حتى يغيّرها المستخدم، **يحوّله middleware إلى `/profile` من
أي مسار** — فلا يستخدم المنصة بكلمة يعرفها غيره.

يُقرأ الحقل من **رمز الجلسة** لا من قاعدة البيانات، لأن middleware يعمل
على Edge حيث لا يعمل Prisma.

بعد تغيير كلمة المرور تُنهى الجلسة إجباريًا. ليس تجميلًا: الرمز يحمل
`mustChangePassword` القديم، وإبطاله يضمن أيضًا ألا تبقى جلسة قائمة
بكلمة مرور تغيّرت.

`changePassword()` لا تستقبل معرّف مستخدم من المتصفح — تأخذه من الجلسة،
فلا يمكن تغيير كلمة مرور شخص آخر مهما عُبث بالطلب. وتتحقق من كلمة المرور
الحالية قبل القبول.

الإدارة تستطيع إعادة تعيين كلمة مرور أي مستخدم من `/settings/users`،
وهو ما يُفعّل الإجبار من جديد.

> الحسابات التجريبية في `db:seed` معفاة من الإجبار لتسهيل التجربة.

### الحماية

`requireAdmin()` في `src/lib/data/admin.ts` تُستدعى في **كل صفحة إدارية
وكل إجراء خادم** — لا في التخطيط وحده. سببان:

1. Next.js ينفّذ التخطيط والصفحة على التوازي
2. إجراءات الخادم (Server Actions) نقاط دخول مستقلة يمكن استدعاؤها
   مباشرةً دون المرور بأي صفحة

أي مستخدم غير إداري يحصل على 404 لا 403 — فلا نكشف وجود المسارات أصلًا.

الإجراءات لا تثق بقيم القوائم المنسدلة: عند إنشاء مقرر يُتحقق أن المدرب
المختار دوره فعلًا `INSTRUCTOR` ونشط، وأن الفصل موجود. وعند التسجيل
يُتحقق أن المستخدم طالب نشط.

قيود إضافية مطبّقة:

- لا يستطيع المدير تعطيل حسابه هو
- كلمات المرور المبدئية تُجزّأ بـ bcrypt ولا تُخزَّن نصًا
- إعادة تسجيل طالب انسحب سابقًا تُعيد تفعيل تسجيله بدل رفض العملية

## الاختبارات

موضوعية بالكامل في هذه المرحلة — تصحيح آلي 100% بلا تدخل من المدرب.

**صح/خطأ يُمثَّل بخيارين** (`صح` و`خطأ`) لا بحقل منطقي. هكذا يتوحّد منطق
التصحيح والعرض بين نوعَي السؤال، ويختفي فرع خاص من الكود.

### المكان

الاختبارات داخل تبويب **المحتوى** لا كتبويب خامس — قاعدة التصميم تحصر
تبويبات المقرر في أربعة، والمرجع في وثيقة المشروع يضع الاختبارات ضمن
محتوى المقرر.

| المسار | الوصول |
|---|---|
| `/courses/[id]/quizzes/new` | المدرب/الإدارة فقط |
| `/courses/[id]/quizzes/[quizId]` | المدرب/الإدارة فقط (صفحة تحرير) |

### منع تسريب الإجابات

`getQuizForEditing()` هي الدالة الوحيدة التي تُحمّل `isCorrect`، وتُستدعى
حصرًا في صفحة التحرير المحمية. صفحة المحتوى تستخدم `getCourseQuizzes()`
التي لا تُحمّل الأسئلة أصلًا — فلا تصل الإجابات إلى متصفح الطالب حتى
كبيانات مخفية.

### قيود مطبّقة

- **لا نشر بلا إجابة صحيحة**: `publishBlockers()` تمنع نشر اختبار بلا
  أسئلة، أو بسؤال بلا إجابة صحيحة، أو بخيار فارغ — اختبار كهذا يستحيل
  تصحيحه. الزر معطّل في الواجهة **والإجراء يرفض** على الخادم.
- **قفل البنية بعد أول محاولة**: لا تُعدَّل الأسئلة ولا تُحذف بعد أن
  يبدأ الطلاب، وإلا لأصبحت الدرجات المسجَّلة بلا معنى.
- **لا حذف لاختبار له محاولات** — الإغلاق بديلًا عنه.
- الإجابة الصحيحة المختارة يُتحقق أنها تنتمي للسؤال نفسه، فلا يُمرَّر
  معرّف خيار من سؤال آخر.
- الدرجة المعتمدة عند تعدد المحاولات: **أعلى محاولة**.

### أداء الطالب والتصحيح الآلي

| المسار | الوصف |
|---|---|
| `/courses/[id]/quizzes/[quizId]` | نظرة عامة: المحاولات السابقة، أفضل نتيجة، زر البدء |
| `.../attempt/[attemptId]` | الأداء قبل التسليم، والنتيجة بعده — نفس المسار |

**عزل الإجابات:** `getAttemptForTaking()` تطلب من الخيارات `{ id, text }`
فقط. حقل `isCorrect` لا يُحمَّل من قاعدة البيانات أصلًا في مسار الأداء،
فلا يوجد في الخادم ليتسرّب.

**الوقت من الخادم لا من المتصفح:** المهلة = `startedAt + timeLimitMin`،
تُحسب في `deadlineOf()` عند كل طلب. العدّاد التنازلي في الواجهة عرضي
فقط ويُسلّم تلقائيًا عند الصفر؛ لو عُبث به أو أُوقف، الخادم يرفض
الإجابات المتأخرة ويُسجّل صفرًا. مهلة السماح دقيقتان لتغطية بطء الشبكة.

**الترتيب العشوائي ثابت لكل محاولة:** الخلط مبني على `attemptId` عبر
`shuffleForAttempt()`، فتحديث الصفحة لا يُعيد ترتيب الأسئلة، ويظل
الترتيب مختلفًا بين محاولة وأخرى.

**عرض النتيجة لا يكشف الإجابات:** الطالب يرى درجته وصواب/خطأ كل سؤال،
لكن **لا يرى الإجابة الصحيحة** — وإلا لتحوّلت صفحة النتيجة إلى مصدر
تسريب لمن لم يؤدِّ الاختبار بعد.

**التحققات عند التسليم** — كلها على الخادم:

- المحاولة تخصّ هذا الطالب وهذا الاختبار وهذا المقرر، والطالب مسجَّل فيه
- لم تُسلَّم من قبل
- كل سؤال مُجاب ينتمي لهذا الاختبار
- كل خيار مختار ينتمي لسؤاله
- لا إجابتان لنفس السؤال
- الأسئلة غير المُجابة تُحتسب صفرًا لا تُتجاهل

**حد المحاولات** يُفرض في `startBlocker()` على الخادم. المحاولة المفتوحة
تُستأنف ولا تُحسب محاولة جديدة.

### الحالات

`DRAFT` مسودة لا يراها الطالب · `PUBLISHED` متاح · `CLOSED` مغلق لا تُقبل
فيه محاولات جديدة مع بقاء الدرجات.

## دفتر الدرجات الموحّد

يقرأ `QuizAttempt` و`Submission` عبر نوع واحد `GradeItem` — وهو ما جعل
تصميمهما بنفس النمط مقصودًا منذ البداية.

| المسار | المحتوى |
|---|---|
| `/grades` (طالب) | كل درجاته عبر جميع مقرراته، مجمّعة حسب المقرر |
| `/grades` (مدرب) | قائمة مقرراته، كل واحد يقود إلى دفتره |
| `/courses/[id]/grades` (مدرب) | مصفوفة: كل طالب × كل عنصر تقييم |
| `/courses/[id]/grades` (طالب) | درجاته في هذا المقرر فقط |

### قواعد الاحتساب

- **درجة الاختبار المعتمدة = أعلى محاولة مُسلَّمة** — نفس القاعدة المعلنة
  للطالب في صفحة الاختبار، لا قاعدة ثانية مخفية في الدفتر.
- **المجموع يُحسب على العناصر المصحّحة فقط** لكل طالب على حدة. طالب لم
  يُصحَّح له عنصر بعد لا يظهر وكأنه أخذ فيه صفرًا — الخلية تعرض `—`
  ولا تدخل في مقامه.
- درجة الواجب المقروءة هي `earnedPoints` أي **بعد** خصم التأخير.

### العدّاد وسجل النشاط

عدّاد "الدرجات" في القائمة يعرض **للمدرب** عدد التسليمات المنتظرة
للتصحيح — وهو العنصر الوحيد القابل للإجراء لديه. أما الطالب فدرجته
معلومة لا إجراء، فلا عدّاد لها؛ تظهر في سجل النشاط بدلًا من ذلك.

سجل النشاط صار يعرض للطالب درجاته المنشورة (اختبارات وواجبات)، وللمدرب
التسليمات التي تنتظر تصحيحه.

## الواجبات

المدرب ينشئ الواجب بدرجة كاملة وموعد تسليم وصيغ ملفات مسموحة وحد حجم؛
الطالب يرفع ملفًا و/أو ملاحظة؛ المدرب يصحّح بدرجة وتعليق.

### التخزين مصمَّم لدفتر الدرجات

`Submission` يتبع نمط `QuizAttempt` عمدًا: `earnedPoints` مقابل
`Assignment.totalPoints`، و`gradedAt`. فدفتر الدرجات الموحّد سيقرأ
المصدرين بنفس الشكل بلا تحويل.

حقلان للدرجة لا واحد:

| الحقل | المعنى |
|---|---|
| `rawPoints` | ما أدخله المدرب قبل أي خصم |
| `earnedPoints` | بعد خصم التأخير — **هذا ما يقرأه دفتر الدرجات** |

الفصل يجعل الخصم شفافًا: المدرب يرى "٩ (قبل الخصم ١٠)" ولا يضطر لحسابه
ذهنيًا، والدرجة المعتمدة تبقى رقمًا واحدًا.

### التأخير

`allowLate` يمنع أو يسمح، و`latePenaltyPercent` يخصم. الخصم يُطبَّق
**على الخادم** في `applyLatePenalty()` عند التصحيح لا في الواجهة.
و`isLate` يُحسب وقت التسليم بمقارنة الخادم لا المتصفح.

### الأمان

- التسليم للطلاب فقط، والاستعلام نفسه يتحقق من التسجيل في المقرر
- التحقق من الصيغة والحجم قبل التوقيع، **و`HEAD` على R2 بعد الرفع** —
  الملف لا يمرّ بخادمنا فهذا هو الفرض الحقيقي، والملف المخالف يُحذف
- تنزيل الملف: مدرب المقرر أو **صاحب التسليم نفسه** فقط؛ أي أحد آخر
  يحصل على 404 ولو خمّن المعرّف
- التصحيح يتحقق أن التسليم يخصّ هذا الواجب في هذا المقرر، وأن الدرجة
  لا تتجاوز الدرجة الكاملة
- إعادة التسليم تُلغي التصحيح السابق تلقائيًا — فلا تبقى درجة معتمدة
  على ملف قديم

## الإعلانات وتتبّع المقروء

| الدور | يرى |
|---|---|
| طالب | المنشورة فقط، مع تمييز غير المقروء |
| مدرب المقرر / إدارة | كل شيء بما فيه المسودات، مع تعديل وحذف |

المثبّت (`isPinned`) أولًا، ثم الأحدث. الإعلان بلا `publishedAt` مسودة.

### لماذا جدول `AnnouncementRead` مستقل

العدّاد بلا تتبّع قراءة رقمٌ بلا معنى. الجدول يربط (إعلان، مستخدم) بقيد
`@@unique` يمنع التكرار، ومنه يُحسب:

- عدّاد "مقرراتي" في القائمة الجانبية = غير المقروء عبر كل المقررات
- عدّاد تبويب "الإعلانات" = غير المقروء في هذا المقرر
- شارة "جديد" على كل إعلان

التعليم كمقروء يتم عبر مكوّن `MarkAnnouncementsRead` الذي يستدعي إجراء
خادم **بعد** العرض، لا داخل الـ render: الكتابة أثناء التصيير تُفسد
التخزين المؤقت وتُنفَّذ مرتين في الوضع الصارم.

الإجراء لا يثق بالمعرّفات الواردة من المتصفح — يقصرها على إعلانات منشورة
في مقرر الطالب مسجَّل فيه فعلًا.

> ملاحظة على التصميم: المخطط الأصلي وضع شارتين على "الدرجات" و"الرسائل".
> بما أن نظاميهما غير مبنيين، نُقلت الشارة إلى "مقرراتي" لتعرض غير
> المقروء من الإعلانات — رقم حقيقي بدل رقمين ثابتين. لإعادتها لاحقًا
> عدّل `badgeTone` في `src/lib/navigation.ts`.

## الرسائل

محادثة **ثنائية** بين طالب ومدربه في سياق مقرر واحد. لا مجموعات ولا
أطراف متعدّدة، ولا مراسلة خارج المقرر: السياق هو ما يمنح الصلاحية.

### الصلاحيات — نقطة واحدة لا تُتجاوز

`resolveThreadAccess` في `src/lib/data/messages.ts` هي البوّابة الوحيدة.
كل قراءة وكل إرسال يمرّان منها، وتُجيب عن سؤال واحد: هل هذا المستخدم
**طرف** في هذه المحادثة تحديدًا؟

| المستخدم | الشرط |
|---|---|
| الطالب | المحادثة محادثته **و** تسجيله في المقرر `ACTIVE` |
| المدرب | المقرر مقرره هو |
| الإدارة | **لا وصول** — الخصوصية ليست بيانات إدارية |

الطالب الذي انسحب من المقرر يفقد المحادثة والعدّاد معًا، لأن الشرط
تسجيل نشط لا مجرّد وجود سابق.

الرفض يكون بـ **404 لا 403**: المحادثة التي لا تخصّك يجب ألّا يُعرف
وجودها أصلًا.

الإجراء الخادمي `sendCourseMessage` لا يكرّر التحقّق بل يستدعي
`sendMessage` التي تستدعي البوّابة. مكانان للتحقّق يعنيان مكانين قد
يفترقان بعد تعديل.

### تتبّع القراءة: لماذا يختلف عن الإعلانات

الإعلان يقرؤه كثيرون فاحتاج `AnnouncementRead` صفًّا لكل قارئ. أما
الرسالة فلها **مستلم واحد بالتعريف**، فجدول وصل كان سينتج صفًّا واحدًا
لكل رسالة دائمًا — نفس المعلومة بجدول وضمّ إضافيين في كل عدّ. لذلك
`Message.readAt` حقل مباشر.

المبدأ المشترك محفوظ: الحالة مخزّنة صراحةً على الخادم، والعدّاد يُحسب
منها لا من تخمين في الواجهة. والشرط `senderId: { not: viewerId }` جوهري
في كل استعلام — بدونه يعدّ المستخدم رسائله هو، وينهار إيصال القراءة.

### أين تظهر

| الموضع | للطالب | للمدرب |
|---|---|---|
| `/messages` | محادثاته عبر كل مقرراته | محادثاته مع كل طلابه |
| تبويب الرسائل في المقرر | محادثته مع المدرب مباشرة | قائمة طلابه المسجّلين |
| عدّاد الشريط الجانبي | رسائل واردة غير مقروءة | نفسه |
| سجل النشاط | حدث بنوع `message` | نفسه |

قائمة المدرب تُبنى من **التسجيلات** لا من المحادثات، فيستطيع بدء محادثة
مع طالب لم يراسله بعد.

## النشر على الإنتاج

### ١. قاعدة البيانات

من لوحة Neon انسخ **رابطين** لا واحدًا:

| المتغيّر | الرابط | يستخدمه |
|---|---|---|
| `DATABASE_URL` | Pooled (يحوي `-pooler`) | التطبيق وقت التشغيل |
| `DIRECT_URL` | Direct (بلا `-pooler`) | `prisma migrate` فقط |

**لماذا الفصل؟** كل نسخة من الدالة الخادمية تفتح اتصالًا بقاعدة
البيانات. بلا pooler تُستنفد حصة الاتصالات تحت الحمل ويبدأ التطبيق
بإرجاع أخطاء اتصال. وبالمقابل، الهجرات تحتاج جلسة مباشرة لأقفال DDL
وقد تتعثّر عبر pooler يعمل بوضع transaction.

اضبط أيضًا `DB_POOL_MAX="2"` أو `"3"` في البيئات الخادمية.

### ٢. Cloudflare R2

أضف نطاق الإنتاج إلى سياسة CORS — بدونه يفشل الرفع من الموقع المنشور:

```json
[
  {
    "AllowedOrigins": [
      "https://masar-bh.com",
      "https://www.masar-bh.com",
      "https://hisab-lms.netlify.app",
      "http://localhost:3000",
      "http://localhost:3100"
    ],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

> ⚠ **حُدِّثت 2026-08-20 مع شراء `masar-bh.com`.** النطاق الجديد **يجب**
> أن يكون في القائمة، وإلا فشل رفع الفيديو منه — والفشل يظهر
> `xhr.onerror` عاريًا لا يميّزه شيء عن رفض CSP. وقد كلّف ذلك جلستين
> من قبل (انظر CLAUDE.md: «الرفع مُنع بسياستنا نحن»). فالتشخيص من
> طرفية المتصفّح لا من الاستثناء.
>
> ويبقى نطاق netlify.app في القائمة: هو ما يعمل أثناء انتشار DNS،
> وهو ما تستعمله معاينات النشر.

### ٣. متغيّرات البيئة في منصة الاستضافة

| المتغيّر | مطلوب |
|---|---|
| `DATABASE_URL` | نعم — pooled |
| `DIRECT_URL` | نعم — direct |
| `AUTH_SECRET` | نعم — **مفتاح جديد غير المستخدم محليًا** |

### ٤. البناء

`npm run build` يشغّل `prisma generate && prisma migrate deploy && next build`.
أي أن الهجرات تُطبَّق تلقائيًا عند كل نشر — لا خطوة يدوية.

> `migrate deploy` يطبّق الهجرات الموجودة فقط ولا ينشئ جديدة ولا يمسح
> بيانات، بخلاف `migrate dev` المخصّص للتطوير.

للبناء المحلي بلا لمس قاعدة البيانات: `npm run build:local`.

### ٥. أول مستخدم

`db:seed` مخصّص للتطوير ويُنشئ حسابات بكلمات معروفة. **لا تشغّله على
الإنتاج.** بدلًا من ذلك أنشئ حساب إدارة واحدًا:

```bash
DATABASE_URL="<الرابط المباشر>" npx tsx -e "
import bcrypt from 'bcryptjs';
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from './src/generated/prisma/client';
const db = new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL! }) });
await db.user.create({ data: {
  username: 'admin', name: 'إدارة مسار', role: 'ADMIN',
  passwordHash: await bcrypt.hash('كلمة-مرور-قوية-مؤقتة', 12),
}});
await db.\$disconnect();
"
```

سيُطالَب بتغيير كلمة المرور عند أول دخول تلقائيًا.

### قائمة تحقق قبل التسليم

- [ ] `AUTH_SECRET` في الإنتاج **يختلف** عن المحلي
- [ ] `DATABASE_URL` هو رابط الـ pooler فعلًا
- [ ] نطاق الإنتاج مضاف في CORS على R2
- [ ] الدلو `Public Access: Disabled`
- [ ] لا يوجد `.env` ولا `.env.local` مرفوعًا إلى Git
- [ ] مفاتيح R2 وNeon المستخدمة أثناء التطوير أُلغيت وأُنشئت غيرها
- [ ] `db:seed` **لم** يُشغَّل على الإنتاج

### الترويسات الأمنية

`next.config.ts` يضيف على كل استجابة: `X-Frame-Options: DENY` (منع
التضمين في إطار)، `X-Content-Type-Options: nosniff`،
`Referrer-Policy`، `Permissions-Policy` تُغلق الكاميرا والميكروفون
والموقع، و`Strict-Transport-Security`. و`poweredByHeader` معطّل.

## ملفات الترحيل (Migrations)

`prisma/migrations/0_init/migration.sql` يُنشئ الأنواع المُعدَّدة والجداول
الأربعة عشر بمفاتيحها وفهارسها. أمر البناء يشغّل `prisma migrate deploy`،
فأي خادم جديد يبني قاعدته من هذا الملف تلقائيًا.

### إن كانت قاعدتك موجودة أصلًا

قاعدة التطوير الحالية أُنشئت غالبًا بـ `prisma db push`، فجداولها موجودة
بلا سجلّ ترحيل. تشغيل `migrate deploy` عليها سيفشل لأنه سيحاول إنشاء
جداول قائمة. الحل هو **الأساس (baseline)**: تُعلِم Prisma أن الترحيل
الأولي مطبَّق فعلًا دون تنفيذه.

```bash
npx prisma migrate resolve --applied 0_init
```

مرة واحدة على كل قاعدة قائمة. القواعد الجديدة الفارغة لا تحتاجه.

### التحقق من عدم وجود انحراف (drift)

هذا الملف كُتب يدويًا لأن بيئة التطوير التي وُلِّد فيها لا تستطيع تنزيل
محرّك Prisma. اختُبر بتطبيقه على قاعدة PostgreSQL فارغة تمامًا: أنشأ
١٤ جدولًا و٣٨ فهرسًا و٢٤ مفتاحًا أجنبيًا، ثم عمل عليه `seed.ts` بعميل
Prisma الحقيقي. وأسماء القيود مطابقة لتسمية Prisma
(`courses_termId_fkey`، `terms_status_startsOn_idx` …).

**تحقّق منه على جهازك مرة واحدة** حيث المحرّك متاح:

```bash
npx prisma migrate diff \
  --from-migrations prisma/migrations \
  --to-schema-datamodel prisma/schema.prisma \
  --shadow-database-url "$DIRECT_URL" \
  --exit-code
```

الخروج بالرمز `0` يعني تطابقًا تامًا. أي رمز آخر يعني انحرافًا، وعندها
احذف المجلد وأعد توليده بـ `npx prisma migrate dev --name init`.

## نموذج البيانات

```
Faculty ──< Course >── User (مدرّب، عبر presenterId)
              │
              ├──< Chapter ──< CourseMaterial (محاضرة أو ملفّ)
              │                      │
              ├──< Product >──< ProductItem ┘        (الباقة تشير إلى دروس بعينها)
              │        │
              │        └──< Enrollment >── User (طالب)
              │
              └──< Quiz · Assignment · Announcement
```

> **⚠ لا `Term` ولا فصولٌ دراسية في هذا المخطّط.** كان الكيان موجودًا في
> نسخة مركز حساب وأُزيل كاملًا في تحوّل مسار — المنصّة سوقٌ لا نظامَ
> تسجيلٍ جامعيّ، والمقرر يُباع متى شاء الطالب لا ضمن فصلٍ مفتوح. **لا
> تُعِده.** (وصفٌ سابق هنا كان يذكره؛ صُحّح 2026-08-30.)

**الشراء لا يُسجَّل في مقرر، بل يمنح باقة.** وهذه هي الفكرة المحورية في
المخطّط كلّه: `Product` باقةٌ داخل مقرر، و`ProductItem` يربطها **بدروسٍ
بعينها**، و`Enrollment` يمنح المشتري تلك الباقة. فسؤال الوصول ليس «هل
الطالب مسجَّل في هذا المقرر؟» بل **«هل يملك باقةً تفتح هذا الدرس؟»**.

**والفصل (`Chapter`) تجميعٌ داخل المسار لا وحدة بيع** — يجمع محاضرات
وحدةٍ دراسية وملفّاتها معًا. و`CourseMaterial.chapterId` قابل للفراغ:
`NULL` يعني «خارج الفصول»، وهي حال كل مادةٍ أُنشئت قبل وجودها.

قيود مطبّقة على مستوى قاعدة البيانات:

- `@@unique([userId, productId])` على `Enrollment` — لا يُمنح الوصول
  مرّتين ولو تكرّر ضغط زرّ التأكيد
- `@@unique([provider, providerPaymentId])` على `Payment` — يمنع
  المعالجة المزدوجة، سواء من نقرةٍ مكرّرة اليوم أو إعادة webhook لاحقًا
- `Course.facultyId` **قابل للفراغ** عمدًا: مقررٌ بلا كلية يظهر تحت
  «مقررات أخرى» ولا يختفي — المنشور لا يصير غير مكتشَف لأن حقلًا تُرك
- `CourseMaterial.chapterId` → `onDelete: SetNull` **لا `Cascade`**:
  حذف فصلٍ يفكّ تجميع موادّه ولا يُهلكها، وإهلاكها كان يقصّ
  `ProductItem` أي حزمًا اشتراها طلاب
- `Quiz.lessonId` / `Assignment.lessonId` → `ON DELETE SET NULL`: حذف
  درسٍ لا يُهلك اختبارًا بمحاولاته ودرجاته

### الصلاحيات

`src/lib/data/courses.ts` يطبّق نطاق الرؤية **داخل الاستعلام نفسه**
لا في الواجهة، فلا يمكن تجاوزه بفتح الرابط مباشرة:

| الدور | يرى |
|---|---|
| طالب | المقررات المسجَّل بها بحالة `ACTIVE` |
| مدرب | المقررات المُسندة إليه |
| إدارة | جميع المقررات |

فتح `/courses/<id>` لمقرر خارج النطاق يُرجع 404، لا صفحة فارغة.

`requireCourseAccess()` تُستدعى في **تخطيط المقرر وفي كل صفحة تبويب على
حدة**، لا في التخطيط وحده: Next.js ينفّذ التخطيط والصفحة على التوازي،
فالتحقق في التخطيط فقط لا يمنع الصفحة من قراءة بيانات ليست للمستخدم.

### تبويبات المقرر

**أربعة تبويبات فقط** (`src/lib/course-tabs.ts`) — المحتوى، الإعلانات،
الدرجات، الرسائل. لا تُضف خامسًا.

> **⚠ المسارات تحت `/learn` لا `/courses`.** `/courses/[slug]` هي
> **واجهة البيع** العامّة (الباقات والأسعار والمعاينة المجانية)، و
> `/learn/[courseId]` هي **قاعة الدرس** الخاصّة. صفحتان مختلفتان لا
> تُخلطان.

| التبويب | المسار |
|---|---|
| المحتوى | `/learn/[courseId]` |
| الإعلانات | `/learn/[courseId]/announcements` |
| الدرجات | `/learn/[courseId]/grades` |
| الرسائل | `/learn/[courseId]/messages` |

الأربعة داخل مجموعة `(tabs)` التي يحمل تخطيطُها `AppPage` وشريطَ
التبويبات، فلا يُعاد بناؤهما عند التنقّل بينها. **وأي صفحةٍ جديدة تحت
`/learn/[courseId]/` تُصيّر `AppPage` فقط إن كانت خارج `(tabs)`** —
داخلها تُعيد جزءًا مجرّدًا، وإلّا ازدوج الغلاف (فخٌّ مسجَّل: كان ينتج
`<main id="main">` مرّتين، وهو HTML غير صالح يُربك رابط التخطّي).

### المسار: فصولٌ ومحاضراتٌ وملفّات في تسلسلٍ واحد

المقرر الحقيقيّ ليس قائمة محاضرات؛ هو فصولٌ، وفي كل فصلٍ محاضراتُه
**وملخّصاته ونماذجه** معًا. ووضعُ الملفّات في شاشةٍ أخرى يجعل ترتيب
الشاشة يخالف ترتيب الدراسة.

- `Chapter` كيانٌ مستقلّ لا نصٌّ على المادة — فيُعاد تسميته مرّة، ولا
  تتفرّق المادة الواحدة بين عنوانين متقاربين.
- `MaterialKind`: `VIDEO` أو `FILE`. والملفّ يُعرض في المسار نفسه
  بأيقونته، **بلا رقم**: الترقيم للدروس، وإعطاؤه لملخّصٍ يجعل «الدرس ٥»
  يعني شيئين.
- **الترقيم متّصلٌ عبر الفصول** — «الدرس ٧» واحدٌ في المقرر كلّه لا
  السابع في فصله، لأن الطالب يشير إليه برقمه في المقرر.
- `chapterId = null` يعني «خارج الفصول»، فتُعرض المادة في مجموعةٍ
  **بلا عنوان ولا طيّ** تمامًا كما كانت قبل وجود الفصول.

⚠ **`groupIntoChapters` تعيش في `src/lib/material-track.ts`** لا في
`lib/data/materials.ts`: الأخير عليه `import "server-only"`،
و`MaterialList` مكوّن **عميل** يحتاج التجميع نفسه — فبقاؤه هناك كان
يُسقط البناء. والتجميع دالّة صرفة لا استعلام، فموضعها وحدةٌ محايدة
يقرؤها الطرفان؛ و`lib/data/materials.ts` يعيد تصديرها ليبقى المدخل
الوحيد لمن يقرأ من الخادم.

**الإدارة** في `LessonPlanner`: إنشاء فصلٍ وحذفه، وقائمةُ إسنادٍ لكل
درس. والإجراءات في `learn/[courseId]/lessons/actions.ts`.

⚠ **وما زال ناقصًا**: مسار الرفع يقبل `video/mp4` وحده
(`ALLOWED_VIDEO_TYPE` في `src/lib/uploads.ts`)، فالمادة من نوع `FILE`
**تُخطَّط ولا تُرفَع بعد**. إتمامها يحتاج توسيع الأنواع المسموحة
و`videoObjectKey` وتحقّق الرفع.

## رفع الفيديو (Cloudflare R2)

المحاضرات المسجّلة تُرفع **مباشرةً من متصفح المدرب إلى R2**؛ الملف لا يمرّ
بخادم Next.js إطلاقًا، فلا تصطدم بحدود حجم الطلب في البيئات الخادمية.

```
المتصفح ──(1) طلب توقيع──► Next.js ──► R2 (توقيع فقط)
   └────────(2) PUT الأجزاء مباشرةً───────► R2
المتصفح ──(3) إتمام──► Next.js ──► R2: Complete + HEAD للتحقق
```

| القيد | القيمة | أين يُفرض |
|---|---|---|
| الحجم الأقصى | 1 جيجابايت | المتصفح + **HEAD على R2 بعد الرفع** |
| الصيغة | `video/mp4` فقط | التوقيع نفسه (R2 يرفض بـ 403) |
| حجم الجزء | 10 ميجابايت | `src/lib/uploads.ts` |

**لماذا التحقق بعد الرفع؟** حد الحجم لا يمكن تضمينه في توقيع `PUT`
(شرط `content-length-range` يحتاج `POST` وR2 لا يدعمه). لذلك بعد إتمام
الرفع يقرأ الخادم بيانات الكائن بـ `HEAD`، ويحذفه ويضع الحالة `FAILED`
إن تجاوز الحد أو اختلف نوعه — قبل أن يظهر لأي طالب.

### متغيّرات البيئة: أين يوضع ماذا

| الملف | المتغيّرات | لماذا |
|---|---|---|
| `.env` | `DATABASE_URL`, `AUTH_SECRET` | **يجب** أن تبقى هنا: `prisma.config.ts` و`prisma/seed.ts` يستخدمان `dotenv` الذي يقرأ `.env` فقط ولا يرى `.env.local` |
| `.env.local` | `R2_*` | يقرأها Next.js فقط وقت التشغيل |

كلاهما مستثنى من Git عبر `.env*` في `.gitignore`.

`R2_ENDPOINT` اختياري — تُبنى تلقائيًا من `R2_ACCOUNT_ID` إن تُركت فارغة.

### إعداد CORS على الدلو — مطلوب

بدونه يفشل الرفع من المتصفح. من لوحة Cloudflare ← R2 ← الدلو ← Settings
← CORS Policy:

```json
[
  {
    "AllowedOrigins": [
      "https://masar-bh.com",
      "https://www.masar-bh.com",
      "https://hisab-lms.netlify.app",
      "http://localhost:3000",
      "http://localhost:3100"
    ],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

`ExposeHeaders: ["ETag"]` **ضروري**: الرفع المجزّأ يحتاج ترويسة `ETag`
من كل جزء لإتمام العملية، والمتصفح يحجبها ما لم تُكشف صراحةً.

### حذف المحتوى

الحذف متاح للمدرب صاحب المقرر وللإدارة فقط، ويمحو **الملف من R2 والسجل
من قاعدة البيانات معًا**.

الترتيب مقصود: الملف أولًا، ثم السجل. لو عُكس وفشل حذف الملف لبقي كائن
يتيم في التخزين بلا سجل يشير إليه — تكلفة صامتة لا يمكن تتبّعها. وإذا
تعذّر الوصول إلى التخزين تُرجع النقطة 502 **ولا تحذف السجل**، فلا يحدث
حذف جزئي.

ملاحظة: `DeleteObject` في S3 ينجح حتى لو لم يكن المفتاح موجودًا، لذلك
نتحقق بـ `HEAD` بعده من اختفاء الكائن فعليًا قبل حذف السجل.

### الرفعات غير المكتملة

R2 يطبّق افتراضيًا قاعدة تُلغي الرفعات المجزّأة غير المكتملة بعد **٧ أيام**
من بدئها، فلا تتراكم الأجزاء المهجورة تلقائيًا. لتقصير المدة إلى يوم
واحد (اختياري): الدلو ← Settings ← Object Lifecycle Rules ← Add rule ←
Abort incomplete multipart uploads.

### المشاهدة

الدلو خاص بالكامل — لا رابط دائم. عنصر `<video>` يشير إلى
`/api/courses/[id]/videos/[materialId]/stream`، وهي نقطة تتحقق من تسجيل
الطالب في المقرر ثم تُحوّل (302) إلى رابط R2 موقّع لساعتين.

الفائدة على وضع الرابط الموقّع في HTML مباشرةً: لا يظهر رابط حامل
للصلاحية في مصدر الصفحة، وتُفحص الصلاحية عند كل طلب تشغيل، وطلبات
النطاق (التنقّل داخل الفيديو) تعمل لأن المتصفح يعيد الطلب إلى R2 مباشرة.

> ملاحظة: presigned URLs في R2 لا تعمل مع النطاقات المخصّصة، فقط نطاق
> `<ACCOUNT_ID>.r2.cloudflarestorage.com`.

## ملاحظة مهمة على Prisma 7

منذ الإصدار السابع لم يعد `url` مسموحًا داخل كتلة `datasource` في
`schema.prisma`؛ وضعه هناك يُنتج الخطأ `P1012`. صار التوزيع كالتالي:

| الغرض | الموقع |
|---|---|
| أوامر CLI (`migrate`, `db seed`, `studio`) | `prisma.config.ts` ← `datasource.url` |
| وقت التشغيل (التطبيق نفسه) | `new PrismaClient({ adapter: new PrismaNeon({ connectionString }) })` في `src/server/db.ts` |

وقت التشغيل يقرأ `DATABASE_URL` المجمّع (pooler)، بينما أوامر Prisma تقرأ
`DIRECT_URL` المباشر من `prisma.config.ts`.

`prisma.config.ts` يستخدم `process.env.DATABASE_URL ?? ""` بدل المساعد
`env()` عمدًا: `env()` يرمي خطأً إذا كان المتغيّر مفقودًا، وكل أوامر Prisma
تحمّل هذا الملف — بما فيها `prisma generate` ضمن `postinstall`. هكذا ينجح
`npm install` حتى في بيئة CI بلا `.env`.

## الحركة والإيماءات

مكتبة واحدة لكليهما: **motion 12** (الاسم الجديد لـ Framer Motion). السبب
أن الحركة والإيماءة شيء واحد هنا — سحب اللوحة يجب أن يتحوّل بسلاسة إلى
حركة إغلاقها حاملًا سرعة الإصبع، ولو كانتا مكتبتين لانفصلت السرعة.

### المصدر الواحد للغة الحركية

`src/lib/motion.ts` يحوي المدد والمنحنيات والنوابض والعتبات. القيم نفسها
مكرّرة كمتغيّرات CSS في `globals.css` (`--dur-*` و`--ease-*`) لأن حالات
التفاعل الصغيرة مكتوبة بـ CSS لا بـ JS. **عند تغيير قيمة، غيّرها في
الموضعين.**

| المدة | القيمة | الاستعمال |
|---|---|---|
| `fast` | 150ms | لون، ضغط زر |
| `base` | 220ms | تبويبات، إغلاق اللوحة |
| `slow` | 320ms | دخول الصفحة، عناصر القوائم |

لا حركة خطية في المشروع: كل المنحنيات `ease-out` أو `ease-in-out`.

### لماذا CSS لبعضها وmotion لبعضها

الأزرار والبطاقات **مكوّنات خادم** تظهر في كل صفحة. تحويلها إلى مكوّنات
عميلة لأجل حركة ضغط يعني شحن JS لكل زر في المنصة. لذلك حالات التفاعل
(`.press` و`.lift` و`.field-motion`) مكتوبة بـ CSS بصفر جافاسكربت، وmotion
مقصور على ما يحتاج تنسيقًا حقيقيًا: الإيماءات، التتابع، انتقال الصفحة،
المؤشّر المنزلق.

### الإيماءات واتجاه القراءة — القاعدة الوحيدة

`src/lib/use-direction.ts` يقرأ `dir` من عنصر `html` ويحوّل الإزاحة
الفيزيائية إلى **منطقية**:

```
logical = physical × (dir === "rtl" ? −1 : +1)
```

ومنها قاعدة واحدة تسري على كل إيماءة في المشروع:

> **منطقي سالب = للأمام** (التبويب التالي، وإخراج اللوحة من الشاشة)
> **منطقي موجب = للخلف** (التبويب السابق)

لا تُكتب كلمة `left` ولا `right` في أي منطق إيماءة. تغيير `dir` إلى `ltr`
يقلب السلوك كله وحده. مُختبَر في الاتجاهين بلمس حقيقي: نفس القيمة المنطقية
(−150) تنتج من سحب **يمينًا** في RTL ومن سحب **يسارًا** في LTR، والوجهة
واحدة في الحالتين.

الاستثناء الوحيد `dragElastic` في `CourseSwipeArea`، لأن motion يسمّي
حافتيه `left` و`right`؛ وحتى هناك تُبنى القيمة من الإشارة لا يدويًا.

### أين تعيش كل حركة

| المكوّن | ما يفعله |
|---|---|
| `motion/MotionRoot` | `reducedMotion="user"` — يُلغي الإزاحة لمن يطلب تقليل الحركة |
| `motion/PageTransition` | دخول/خروج الصفحة، مع تجميد الموجّه أثناء الخروج |
| `motion/Stagger` | `StaggerList` + `StaggerItem` بديلا `ol`/`li` بلا عقد إضافية |
| `shell/BottomNav` | شريط الهاتف السفليّ: علامةٌ منزلقة + حالة متفائلة (بدل القائمة المنسحبة منذ 2026-09-14) |
| `courses/CourseSwipeArea` | سحب بين التبويبات، للمس فقط |
| `courses/CourseTabs` | مؤشّر منزلق بـ `layoutId` |

### تحذير: استيراد داخلي من Next

`PageTransition` يستورد `LayoutRouterContext` من
`next/dist/shared/lib/app-router-context.shared-runtime` — لا بديل عام له.
بدونه تومض الصفحة الخارجة بمحتوى الصفحة الجديدة قبل اختفائها. إن كسره
تحديث لاحق لـ Next سيفشل **البناء** بخطأ استيراد واضح لا بسلوك صامت،
وحينها احذف غلاف `FrozenRouter` وتبقى حركة الدخول تعمل.

### سياسة أمان المحتوى (CSP)

مبنية في `src/lib/csp.ts` ومركّبة في `middleware.ts`. تستخدم **nonce
جديدًا لكل طلب** مع `strict-dynamic` بدل `'unsafe-inline'`، فأي نص برمجي
يحقنه مهاجم يُرفض لأنه لا يحمل الـ nonce.

نطاق R2 يُقرأ من `R2_ENDPOINT` ويُضاف إلى `media-src` و`connect-src`
و`img-src` — بدونه يُحجب تشغيل الفيديو والرفع معًا.

**نتيجة مهمة**: صفحة مولَّدة مسبقًا تُحفظ بنصوص بلا nonce فتُحجب كاملةً.
لذلك `/login` و`/forgot-password` معلَّمتان `force-dynamic`. أي صفحة عامة
جديدة تحتاج نفس العلامة، وإلا ظهرت بيضاء في الإنتاج.

## تطبيق ويب تقدّمي (PWA)

المنصة قابلة للتثبيت على الشاشة الرئيسية في أندرويد وiOS.

### الأيقونات

تُشتقّ آليًّا من `assets/logo-source.png` (انظر «الشعار» أعلاه)، وتُركَّب
على `--color-ink` — وهو نفسه `theme_color` و`background_color` في البيان،
فتذوب شاشةُ إقلاع النظام في الأيقونة بلا حدٍّ مرئيّ.

| الملف | المقاس | الغرض |
|---|---|---|
| `icon-192/512.png` | تغطية ٧٨٪ | `purpose: any` |
| `icon-maskable-192/512.png` | تغطية ٥٦٪ | `purpose: maskable` |
| `apple-touch-icon.png` | ١٨٠×١٨٠ | iOS |

**لماذا نسختان:** أندرويد يقتطع أيقونة `maskable` بشكل الجهاز — دائرة أو
مربع مستدير — ويضمن سلامة **٨٠٪ الوسطى** فقط. لذلك محتواها أصغر بهامش
واسع: يُقتطع الهامش لا الشعار. وبلا نسخة maskable يضع أندرويد الأيقونة
داخل مربع أبيض ثم يقتطعه، فتظهر حافة بيضاء حول شعار داكن.

**آيفون:** سفاري لا يقرأ `icons` من البيان — يقرأ `apple-touch-icon`
وحدها، وبدونها يضع لقطة مصغّرة من الصفحة. والأيقونة بلا شفافية لأن iOS
يحوّل الشفاف إلى أسود صلب ويضع زواياه المستديرة بنفسه.

### شاشة الإقلاع — للتطبيق المثبَّت وحده

`src/components/brand/PwaLaunch.tsx` تسدّ الفجوة بين شاشة النظام الساكنة
وأوّل إطارٍ يرسمه التطبيق: الشعار يستقرّ صاعدًا، ثمّ يُمدّ خيطُ الطريق من
**بداية السطر** (يمينًا في العربية)، ثمّ السطر التعريفيّ — ثم تتلاشى.

- **شرطها `@media (display-mode: standalone)` في CSS لا في جافاسكربت.**
  الكشف بـ`matchMedia` لا يقع إلا بعد الترطيب، فيومض محتوى التطبيق قبل أن
  تُركَّب الشاشة فوقه — أي أن العلاج يُحدث العيب الذي وُجد لعلاجه. ولذلك
  هي **مكوّن خادم بصفر كيلوبايت JS**.
- **`pointer-events: none` طوال عمرها** — زخرفةٌ فوق تطبيقٍ جاهز؛ لو تأخّر
  إخفاؤها بقي التطبيق مستعملًا تحتها.
- `transform-origin` لا يقبل الكلمات المنطقية، فاتجاه الطريق مشروط
  بـ`html[dir="rtl"]`. المقيس في المتصفّح: `208px 1px` أي الحافّة اليمنى.
- **عند `prefers-reduced-motion: reduce` تُسقَط كاملةً.** كلّ قيمتها في
  الحركة، فمن طلب حركةً أقلّ لا يُعطى نسخةً ساكنة تؤخّره ثانيةً ونصفًا.

المقيس: ‏٤٢٠ms الشعار مكتملٌ والطريق ممدود · ‏١٠٠٠ms السطر ظاهر ·
‏١٥٠٠ms `opacity: 0` و`visibility: hidden`.

### عامل الخدمة — موجود ولا يخزّن شيئًا

كروم لا يعرض "تثبيت التطبيق" إلا لموقع يملك بيانًا صالحًا **وعامل خدمة
يعالج `fetch`**. بدونه يبقى الخيار "إضافة اختصار" يفتح في تبويب متصفح.

لكنه يمرّر كل طلب إلى الشبكة بلا تخزين: المنصة خلف تسجيل دخول وصفحاتها
تُصيَّر لكل مستخدم بدوره. تخزين درجات طالب أو محادثته في ذاكرة المتصفح
يعني أن يراها من يفتح الجهاز بعده. **القيمة هنا التثبيت لا العمل دون
اتصال** — وأي تخزين لاحق يحتاج تصميم إبطال مرتبطًا بالجلسة.

### تفاصيل لا تُنسى

- `manifest.webmanifest` و`sw.js` **مستثنيان من middleware**. لو مرّا منه
  لأعاد الزائر غير المسجّل إلى صفحة الدخول بدلهما، فيختفي خيار التثبيت.
- `worker-src` و`manifest-src` مصرَّح بهما في CSP.
- `viewport-fit=cover` مع `env(safe-area-inset-*)` في `globals.css`:
  عند التثبيت على آيفون تمتدّ الصفحة تحت النتوء وشريط الإيماءة.
- Next يُصدر `mobile-web-app-capable` وحده؛ أُضيف
  `apple-mobile-web-app-capable` يدويًا لأجل iOS أقدم من 15.4.

## كلمات المرور في الواجهة

### الإظهار والإخفاء

`PasswordField` مكوّن واحد يخدم كل حقول كلمة المرور: الدخول، تغيير
كلمة المرور، إنشاء حساب من الإدارة، وإعادة التعيين.

`type` وحده يتبدّل — الحقل لا يُعاد تركيبه فلا يفقد التركيز ولا موضع
المؤشّر. والزرّ يستخدم `aria-pressed` لا تسمية متبدّلة، فيعلن قارئ الشاشة
الحالة بدل أن يبدو الزرّ وكأنه تغيّر إلى زرّ آخر.

حقل "كلمة المرور المبدئية" في الإدارة كان `type="text"` مكشوفًا دائمًا.
صار مخفيًا بزرّ إظهار: نفس القدرة على قراءتها وتسليمها، بلا بقائها
معروضة أمام كل من يمرّ خلف الشاشة.

### مؤشّر القوة — إرشادي بحت

`estimateStrength` في `src/lib/password-strength.ts`. **لا يُستدعى في أي
مسار تحقّق ولا يُمرَّر إلى أي `disabled`.** مكوّن العرض لا يستقبل دالة
ولا يصدر حدثًا، فلا يستطيع منع إرسال حتى لو أراد مطوّر لاحق ذلك سهوًا.

وهو ليس قياسًا لمقاومة الكسر: القياس الحقيقي يحتاج مكتبة كـ zxcvbn
بحجم مئات الكيلوبايتات. ما يفعله: يكافئ الطول والتنوّع، ويعاقب الأنماط
الواضحة. يكفي ليقول "قصيرة" أو "كلها أرقام"، ولا يدّعي أكثر.

**الحدّ الوحيد الفعلي هو `min(8)` على الخادم** — قاعدة سابقة مستقلة عن
المؤشّر. كلمة `aaaaaaaa` تُقيَّم "ضعيفة" وتُنشئ الحساب بنجاح.

## المصادقة

Auth.js v5 مع Credentials وجلسات JWT تحمل الدور.

الملفات:

- `src/auth.config.ts` — الإعدادات الصالحة لبيئة Edge (بلا Prisma)، تُستخدم في
  `middleware.ts`. تحتوي `trustHost: true` وهي **ضرورية** عند الاستضافة
  الذاتية خارج Vercel، وإلا يرفض Auth.js كل الطلبات بخطأ `UntrustedHost`.
- `src/auth.ts` — الإعداد الكامل مع مزوّد Credentials وقراءة قاعدة البيانات.
  يعمل على Node لأن Prisma لا يعمل على Edge.
- `src/middleware.ts` — يحوّل غير المسجّلين إلى `/login?next=...` ويمنع
  المسجّلين من فتح صفحة الدخول.
- `src/types/next-auth.d.ts` — توسعة أنواع الجلسة بـ `role` و`username`.
  لاحظ أن توسعة JWT تستهدف `@auth/core/jwt` لا `next-auth/jwt`.

ملاحظات أمنية مطبّقة:

- كلمات المرور بـ bcrypt بمعامل تكلفة 12 — لا تُخزَّن كلمة المرور الأصلية
- المقارنة تُنفَّذ دائمًا حتى لو لم يوجد المستخدم، حتى لا يكشف زمن الاستجابة
  أي أسماء المستخدمين موجودة
- الحساب المعطّل يُميَّز برسالة مستقلة عن بيانات الدخول الخاطئة
- التحقق من الجلسة يتم في `middleware` و في تخطيط `(app)` على الخادم معًا

```bash
npx tsx --tsconfig tsconfig.script.json scripts/course-transition-regression.mts
```
