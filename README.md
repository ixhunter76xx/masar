# منصة مركز حساب — Hisab LMS

منصة تعليمية إلكترونية (LMS) لمركز حساب للتعليم والتدريب.
مبنية بـ Next.js 15 (App Router) و TypeScript و Tailwind CSS v4، بدعم RTL كامل.

## التشغيل

### أ) مع Neon (قاعدة بيانات سحابية)

```bash
cp .env.example .env
```

ثم افتح `.env` وعبّئ قيمتين:

- `DATABASE_URL` — رابط Neon. اختر **Direct connection** لا Pooled،
  لأن `prisma migrate` يحتاج اتصالاً مباشراً. يجب أن ينتهي بـ `?sslmode=require`.
- `AUTH_SECRET` — ولّده بـ:
  `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`

ثم:

```bash
npm install        # يشغّل prisma generate تلقائيًا
npm run db:migrate # إنشاء الجداول على Neon
npm run db:seed    # حسابات + فصلان دراسيان + ٤ مقررات + تسجيلات
npm run dev        # http://localhost:3000 → /login
```

> `npm run db:up` **غير مطلوب** مع Neon — فهو يشغّل PostgreSQL محليًا عبر Docker.

### ب) مع Docker محليًا (بديل)

```bash
cp .env.example .env    # اترك رابط Docker الموجود في التعليقات
npm install
npm run db:up           # يشغّل PostgreSQL في حاوية
npm run db:migrate
npm run db:seed
npm run dev
```

## الهيكل العام والتنقّل

الشريط الجانبي مثبّت يمين الشاشة بعرض 260px من مقاس `lg` فأعلى، وتحته
يتحوّل إلى لوحة منسحبة من اليمين.

قواعد من نظام التصميم مطبّقة في `src/lib/navigation.ts`:

- **ستة عناصر جذرية كحد أقصى** — النشاط، مقرراتي، الدرجات، الرسائل،
  الملف الشخصي، الإعدادات. لا تُضف عنصرًا سابعًا؛ أي وظيفة جديدة تندرج
  تحت أحدها.
- العنصر النشط: خط رأسي + خلفية خفيفة، بلا لون نص صاخب.
- العدّادات تظهر فقط عند وجود عناصر تتطلب إجراءً من المستخدم.
- الأيقونات أحادية اللون بوزن واحد (`lucide-react` بسماكة 1.75).

### الاتجاه: خصائص منطقية فقط

لا يوجد في المشروع أي خاصية اتجاه فيزيائية (`left`, `right`, `ml`, `mr`,
`pl`, `pr`, `border-l`, `border-r`, `text-left`, `text-right`). كل شيء
منطقي، فينقلب التخطيط كاملًا بتغيير `dir` وحده دون لمس أي كلاس:

| الاستخدام | الكلاس | يُنتج | RTL | LTR |
|---|---|---|---|---|
| تثبيت الشريط الجانبي | `start-0` | `inset-inline-start` | يمين | يسار |
| حدّ الشريط | `border-e` | `border-inline-end` | يسار | يمين |
| هامش المحتوى | `lg:ms-[260px]` | `margin-inline-start` | يمين | يسار |
| خط العنصر النشط | `before:end-0` | `inset-inline-end` | يسار | يمين |
| حشوة بند القائمة | `ps-3` / `pe-4` | `padding-inline-*` | — | — |

ترتيب عناصر بند القائمة يعتمد على تدفّق DOM الطبيعي (أيقونة ← نص ← عدّاد)
لا على `order`، فينقلب هو الآخر تلقائيًا: الأيقونة على الجهة الابتدائية
دائمًا (يمين في RTL، يسار في LTR).

لإضافة الإنجليزية لاحقًا يكفي تغيير `lang` و`dir` في `src/app/layout.tsx`
(أو تمريرهما من التوجيه i18n) — لا تعديل على أي مكوّن.

### الشعار

مكوّن `Logo` يختار النسخة تلقائيًا حسب المقاس:

| النسخة | الملف | متى |
|---|---|---|
| `full` | `logo-hisab.png` | 64px فأكبر — شاشة الدخول |
| `mark` | `logo-hisab-mark.png` | أقل من 64px — القائمة والرأسية |

السبب أن كتابة "مركز حساب للتعليم والتدريب" داخل الشعار تصبح غير مقروءة
تحت 64px. يمكن التجاوز يدويًا بـ `variant="full"` أو `variant="mark"`.

### لا بيانات وهمية

كل ما يظهر في الواجهة يأتي من قاعدة البيانات. سجل النشاط يدمج الإعلانات
المنشورة والمحاضرات الجاهزة عبر مقررات المستخدم؛ ولإضافة مصدر جديد
(درجات، واجبات) يكفي دمجه في `getActivityFeed`.

العدّادات التي لا جداول لها بعد (`/grades`, `/messages`) تُرجع صفرًا،
و`CountBadge` لا يعرض شيئًا عند الصفر — فلا شارات كاذبة.

## المنطقة الإدارية

قاعدة التصميم تمنع عنصرًا سابعًا في القائمة الجانبية، لذلك تعيش أدوات
الإدارة **داخل "الإعدادات"** بتبويبات فرعية:

| المسار | الوظيفة |
|---|---|
| `/settings/terms` | إنشاء الفصول، أرشفتها وإعادة تنشيطها |
| `/settings/courses` | إنشاء المقررات وإسناد المدربين |
| `/settings/courses/[id]` | تسجيل الطلاب وإزالتهم |
| `/settings/users` | إنشاء الحسابات، تعطيلها وتفعيلها |

`/settings` يحوّل الإدارة تلقائيًا إلى `/settings/terms`، ويعرض لغيرهم
صفحة التفضيلات العادية.

### الحماية

`requireAdmin()` في `src/lib/data/admin.ts` تُستدعى في **كل صفحة إدارية
وكل إجراء خادم** — لا في التخطيط وحده. سببان:

1. Next.js ينفّذ التخطيط والصفحة على التوازي
2. إجراءات الخادم (Server Actions) نقاط دخول مستقلة يمكن استدعاؤها
   مباشرةً دون المرور بأي صفحة

أي مستخدم غير إداري يحصل على 404 لا 403 — فلا نكشف وجود المسارات أصلًا.

الإجراءات لا تثق بقيم القوائم المنسدلة: عند إنشاء مقرر يُتحقق أن المدرب
المختار دوره فعلًا `INSTRUCTOR` ونشط، وأن الفصل موجود. وعند التسجيل
يُتحقق أن المستخدم طالب نشط.

قيود إضافية مطبّقة:

- لا يستطيع المدير تعطيل حسابه هو
- كلمات المرور المبدئية تُجزّأ بـ bcrypt ولا تُخزَّن نصًا
- إعادة تسجيل طالب انسحب سابقًا تُعيد تفعيل تسجيله بدل رفض العملية

## الاختبارات

موضوعية بالكامل في هذه المرحلة — تصحيح آلي 100% بلا تدخل من المدرب.

**صح/خطأ يُمثَّل بخيارين** (`صح` و`خطأ`) لا بحقل منطقي. هكذا يتوحّد منطق
التصحيح والعرض بين نوعَي السؤال، ويختفي فرع خاص من الكود.

### المكان

الاختبارات داخل تبويب **المحتوى** لا كتبويب خامس — قاعدة التصميم تحصر
تبويبات المقرر في أربعة، والمرجع في وثيقة المشروع يضع الاختبارات ضمن
محتوى المقرر.

| المسار | الوصول |
|---|---|
| `/courses/[id]/quizzes/new` | المدرب/الإدارة فقط |
| `/courses/[id]/quizzes/[quizId]` | المدرب/الإدارة فقط (صفحة تحرير) |

### منع تسريب الإجابات

`getQuizForEditing()` هي الدالة الوحيدة التي تُحمّل `isCorrect`، وتُستدعى
حصرًا في صفحة التحرير المحمية. صفحة المحتوى تستخدم `getCourseQuizzes()`
التي لا تُحمّل الأسئلة أصلًا — فلا تصل الإجابات إلى متصفح الطالب حتى
كبيانات مخفية.

### قيود مطبّقة

- **لا نشر بلا إجابة صحيحة**: `publishBlockers()` تمنع نشر اختبار بلا
  أسئلة، أو بسؤال بلا إجابة صحيحة، أو بخيار فارغ — اختبار كهذا يستحيل
  تصحيحه. الزر معطّل في الواجهة **والإجراء يرفض** على الخادم.
- **قفل البنية بعد أول محاولة**: لا تُعدَّل الأسئلة ولا تُحذف بعد أن
  يبدأ الطلاب، وإلا لأصبحت الدرجات المسجَّلة بلا معنى.
- **لا حذف لاختبار له محاولات** — الإغلاق بديلًا عنه.
- الإجابة الصحيحة المختارة يُتحقق أنها تنتمي للسؤال نفسه، فلا يُمرَّر
  معرّف خيار من سؤال آخر.
- الدرجة المعتمدة عند تعدد المحاولات: **أعلى محاولة**.

### أداء الطالب والتصحيح الآلي

| المسار | الوصف |
|---|---|
| `/courses/[id]/quizzes/[quizId]` | نظرة عامة: المحاولات السابقة، أفضل نتيجة، زر البدء |
| `.../attempt/[attemptId]` | الأداء قبل التسليم، والنتيجة بعده — نفس المسار |

**عزل الإجابات:** `getAttemptForTaking()` تطلب من الخيارات `{ id, text }`
فقط. حقل `isCorrect` لا يُحمَّل من قاعدة البيانات أصلًا في مسار الأداء،
فلا يوجد في الخادم ليتسرّب.

**الوقت من الخادم لا من المتصفح:** المهلة = `startedAt + timeLimitMin`،
تُحسب في `deadlineOf()` عند كل طلب. العدّاد التنازلي في الواجهة عرضي
فقط ويُسلّم تلقائيًا عند الصفر؛ لو عُبث به أو أُوقف، الخادم يرفض
الإجابات المتأخرة ويُسجّل صفرًا. مهلة السماح دقيقتان لتغطية بطء الشبكة.

**الترتيب العشوائي ثابت لكل محاولة:** الخلط مبني على `attemptId` عبر
`shuffleForAttempt()`، فتحديث الصفحة لا يُعيد ترتيب الأسئلة، ويظل
الترتيب مختلفًا بين محاولة وأخرى.

**عرض النتيجة لا يكشف الإجابات:** الطالب يرى درجته وصواب/خطأ كل سؤال،
لكن **لا يرى الإجابة الصحيحة** — وإلا لتحوّلت صفحة النتيجة إلى مصدر
تسريب لمن لم يؤدِّ الاختبار بعد.

**التحققات عند التسليم** — كلها على الخادم:

- المحاولة تخصّ هذا الطالب وهذا الاختبار وهذا المقرر، والطالب مسجَّل فيه
- لم تُسلَّم من قبل
- كل سؤال مُجاب ينتمي لهذا الاختبار
- كل خيار مختار ينتمي لسؤاله
- لا إجابتان لنفس السؤال
- الأسئلة غير المُجابة تُحتسب صفرًا لا تُتجاهل

**حد المحاولات** يُفرض في `startBlocker()` على الخادم. المحاولة المفتوحة
تُستأنف ولا تُحسب محاولة جديدة.

### الحالات

`DRAFT` مسودة لا يراها الطالب · `PUBLISHED` متاح · `CLOSED` مغلق لا تُقبل
فيه محاولات جديدة مع بقاء الدرجات.

## الواجبات

المدرب ينشئ الواجب بدرجة كاملة وموعد تسليم وصيغ ملفات مسموحة وحد حجم؛
الطالب يرفع ملفًا و/أو ملاحظة؛ المدرب يصحّح بدرجة وتعليق.

### التخزين مصمَّم لدفتر الدرجات

`Submission` يتبع نمط `QuizAttempt` عمدًا: `earnedPoints` مقابل
`Assignment.totalPoints`، و`gradedAt`. فدفتر الدرجات الموحّد سيقرأ
المصدرين بنفس الشكل بلا تحويل.

حقلان للدرجة لا واحد:

| الحقل | المعنى |
|---|---|
| `rawPoints` | ما أدخله المدرب قبل أي خصم |
| `earnedPoints` | بعد خصم التأخير — **هذا ما يقرأه دفتر الدرجات** |

الفصل يجعل الخصم شفافًا: المدرب يرى "٩ (قبل الخصم ١٠)" ولا يضطر لحسابه
ذهنيًا، والدرجة المعتمدة تبقى رقمًا واحدًا.

### التأخير

`allowLate` يمنع أو يسمح، و`latePenaltyPercent` يخصم. الخصم يُطبَّق
**على الخادم** في `applyLatePenalty()` عند التصحيح لا في الواجهة.
و`isLate` يُحسب وقت التسليم بمقارنة الخادم لا المتصفح.

### الأمان

- التسليم للطلاب فقط، والاستعلام نفسه يتحقق من التسجيل في المقرر
- التحقق من الصيغة والحجم قبل التوقيع، **و`HEAD` على R2 بعد الرفع** —
  الملف لا يمرّ بخادمنا فهذا هو الفرض الحقيقي، والملف المخالف يُحذف
- تنزيل الملف: مدرب المقرر أو **صاحب التسليم نفسه** فقط؛ أي أحد آخر
  يحصل على 404 ولو خمّن المعرّف
- التصحيح يتحقق أن التسليم يخصّ هذا الواجب في هذا المقرر، وأن الدرجة
  لا تتجاوز الدرجة الكاملة
- إعادة التسليم تُلغي التصحيح السابق تلقائيًا — فلا تبقى درجة معتمدة
  على ملف قديم

## الإعلانات وتتبّع المقروء

| الدور | يرى |
|---|---|
| طالب | المنشورة فقط، مع تمييز غير المقروء |
| مدرب المقرر / إدارة | كل شيء بما فيه المسودات، مع تعديل وحذف |

المثبّت (`isPinned`) أولًا، ثم الأحدث. الإعلان بلا `publishedAt` مسودة.

### لماذا جدول `AnnouncementRead` مستقل

العدّاد بلا تتبّع قراءة رقمٌ بلا معنى. الجدول يربط (إعلان، مستخدم) بقيد
`@@unique` يمنع التكرار، ومنه يُحسب:

- عدّاد "مقرراتي" في القائمة الجانبية = غير المقروء عبر كل المقررات
- عدّاد تبويب "الإعلانات" = غير المقروء في هذا المقرر
- شارة "جديد" على كل إعلان

التعليم كمقروء يتم عبر مكوّن `MarkAnnouncementsRead` الذي يستدعي إجراء
خادم **بعد** العرض، لا داخل الـ render: الكتابة أثناء التصيير تُفسد
التخزين المؤقت وتُنفَّذ مرتين في الوضع الصارم.

الإجراء لا يثق بالمعرّفات الواردة من المتصفح — يقصرها على إعلانات منشورة
في مقرر الطالب مسجَّل فيه فعلًا.

> ملاحظة على التصميم: المخطط الأصلي وضع شارتين على "الدرجات" و"الرسائل".
> بما أن نظاميهما غير مبنيين، نُقلت الشارة إلى "مقرراتي" لتعرض غير
> المقروء من الإعلانات — رقم حقيقي بدل رقمين ثابتين. لإعادتها لاحقًا
> عدّل `badgeTone` في `src/lib/navigation.ts`.

## نموذج البيانات

```
Term ──< Course >── User (مدرب)
             │
             └──< Enrollment >── User (طالب)
```

**الفصل الدراسي كيان مستقل** (`Term`) لا حقل نصي، لأن المشروع يتطلب
تنظيم المقررات حسب الفصل وأرشفة المنتهية منها:

| الحقل | النوع | ملاحظة |
|---|---|---|
| `name` | `String @unique` | "2025/2026 — الفصل الثاني" |
| `startsOn` / `endsOn` | `Date` | حدود الفصل |
| `status` | `TermStatus` | `ACTIVE` أو `ARCHIVED` |

قيود مطبّقة على مستوى قاعدة البيانات:

- `Course.termId` مفتاح أجنبي إلى `Term` — لا نص حر
- `@@unique([termId, code])` — رمز المقرر فريد داخل الفصل، ويجوز تكراره
  عبر الفصول (نفس المقرر يُطرح كل فصل)
- `@@unique([studentId, courseId])` — لا يُسجَّل الطالب مرتين في مقرر
- `onDelete: Restrict` على المقرر والفصل — لا يُحذف فصل له مقررات
- `onDelete: Cascade` على التسجيلات — حذف الطالب أو المقرر يزيل تسجيلاته

### الصلاحيات

`src/lib/data/courses.ts` يطبّق نطاق الرؤية **داخل الاستعلام نفسه**
لا في الواجهة، فلا يمكن تجاوزه بفتح الرابط مباشرة:

| الدور | يرى |
|---|---|
| طالب | المقررات المسجَّل بها بحالة `ACTIVE` |
| مدرب | المقررات المُسندة إليه |
| إدارة | جميع المقررات |

فتح `/courses/<id>` لمقرر خارج النطاق يُرجع 404، لا صفحة فارغة.

`requireCourseAccess()` تُستدعى في **تخطيط المقرر وفي كل صفحة تبويب على
حدة**، لا في التخطيط وحده: Next.js ينفّذ التخطيط والصفحة على التوازي،
فالتحقق في التخطيط فقط لا يمنع الصفحة من قراءة بيانات ليست للمستخدم.

### تبويبات المقرر

**أربعة تبويبات فقط** (`src/lib/course-tabs.ts`) — المحتوى، الإعلانات،
الدرجات، الرسائل. لا تُضف خامسًا.

| التبويب | المسار |
|---|---|
| المحتوى | `/courses/[id]` |
| الإعلانات | `/courses/[id]/announcements` |
| الدرجات | `/courses/[id]/grades` |
| الرسائل | `/courses/[id]/messages` |

بطاقة رأس المقرر والتبويبات في `layout.tsx`، فلا يُعاد بناؤها عند التنقّل
بين التبويبات. عدّادات التبويبات في `src/lib/data/course-tab-counts.ts`
ترجع أصفارًا حاليًا (لا جداول للإعلانات والرسائل بعد)، والشارات لا تظهر
عند الصفر — فستظهر تلقائيًا فور ربط الجداول.

## رفع الفيديو (Cloudflare R2)

المحاضرات المسجّلة تُرفع **مباشرةً من متصفح المدرب إلى R2**؛ الملف لا يمرّ
بخادم Next.js إطلاقًا، فلا تصطدم بحدود حجم الطلب في البيئات الخادمية.

```
المتصفح ──(1) طلب توقيع──► Next.js ──► R2 (توقيع فقط)
   └────────(2) PUT الأجزاء مباشرةً───────► R2
المتصفح ──(3) إتمام──► Next.js ──► R2: Complete + HEAD للتحقق
```

| القيد | القيمة | أين يُفرض |
|---|---|---|
| الحجم الأقصى | 1 جيجابايت | المتصفح + **HEAD على R2 بعد الرفع** |
| الصيغة | `video/mp4` فقط | التوقيع نفسه (R2 يرفض بـ 403) |
| حجم الجزء | 10 ميجابايت | `src/lib/uploads.ts` |

**لماذا التحقق بعد الرفع؟** حد الحجم لا يمكن تضمينه في توقيع `PUT`
(شرط `content-length-range` يحتاج `POST` وR2 لا يدعمه). لذلك بعد إتمام
الرفع يقرأ الخادم بيانات الكائن بـ `HEAD`، ويحذفه ويضع الحالة `FAILED`
إن تجاوز الحد أو اختلف نوعه — قبل أن يظهر لأي طالب.

### متغيّرات البيئة: أين يوضع ماذا

| الملف | المتغيّرات | لماذا |
|---|---|---|
| `.env` | `DATABASE_URL`, `AUTH_SECRET` | **يجب** أن تبقى هنا: `prisma.config.ts` و`prisma/seed.ts` يستخدمان `dotenv` الذي يقرأ `.env` فقط ولا يرى `.env.local` |
| `.env.local` | `R2_*` | يقرأها Next.js فقط وقت التشغيل |

كلاهما مستثنى من Git عبر `.env*` في `.gitignore`.

`R2_ENDPOINT` اختياري — تُبنى تلقائيًا من `R2_ACCOUNT_ID` إن تُركت فارغة.

### إعداد CORS على الدلو — مطلوب

بدونه يفشل الرفع من المتصفح. من لوحة Cloudflare ← R2 ← الدلو ← Settings
← CORS Policy:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "https://lms.hisab.edu"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

`ExposeHeaders: ["ETag"]` **ضروري**: الرفع المجزّأ يحتاج ترويسة `ETag`
من كل جزء لإتمام العملية، والمتصفح يحجبها ما لم تُكشف صراحةً.

### حذف المحتوى

الحذف متاح للمدرب صاحب المقرر وللإدارة فقط، ويمحو **الملف من R2 والسجل
من قاعدة البيانات معًا**.

الترتيب مقصود: الملف أولًا، ثم السجل. لو عُكس وفشل حذف الملف لبقي كائن
يتيم في التخزين بلا سجل يشير إليه — تكلفة صامتة لا يمكن تتبّعها. وإذا
تعذّر الوصول إلى التخزين تُرجع النقطة 502 **ولا تحذف السجل**، فلا يحدث
حذف جزئي.

ملاحظة: `DeleteObject` في S3 ينجح حتى لو لم يكن المفتاح موجودًا، لذلك
نتحقق بـ `HEAD` بعده من اختفاء الكائن فعليًا قبل حذف السجل.

### الرفعات غير المكتملة

R2 يطبّق افتراضيًا قاعدة تُلغي الرفعات المجزّأة غير المكتملة بعد **٧ أيام**
من بدئها، فلا تتراكم الأجزاء المهجورة تلقائيًا. لتقصير المدة إلى يوم
واحد (اختياري): الدلو ← Settings ← Object Lifecycle Rules ← Add rule ←
Abort incomplete multipart uploads.

### المشاهدة

الدلو خاص بالكامل — لا رابط دائم. عنصر `<video>` يشير إلى
`/api/courses/[id]/videos/[materialId]/stream`، وهي نقطة تتحقق من تسجيل
الطالب في المقرر ثم تُحوّل (302) إلى رابط R2 موقّع لساعتين.

الفائدة على وضع الرابط الموقّع في HTML مباشرةً: لا يظهر رابط حامل
للصلاحية في مصدر الصفحة، وتُفحص الصلاحية عند كل طلب تشغيل، وطلبات
النطاق (التنقّل داخل الفيديو) تعمل لأن المتصفح يعيد الطلب إلى R2 مباشرة.

> ملاحظة: presigned URLs في R2 لا تعمل مع النطاقات المخصّصة، فقط نطاق
> `<ACCOUNT_ID>.r2.cloudflarestorage.com`.

## ملاحظة مهمة على Prisma 7

منذ الإصدار السابع لم يعد `url` مسموحًا داخل كتلة `datasource` في
`schema.prisma`؛ وضعه هناك يُنتج الخطأ `P1012`. صار التوزيع كالتالي:

| الغرض | الموقع |
|---|---|
| أوامر CLI (`migrate`, `db seed`, `studio`) | `prisma.config.ts` ← `datasource.url` |
| وقت التشغيل (التطبيق نفسه) | `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })` في `src/server/db.ts` |

كلاهما يقرأ `DATABASE_URL` من `.env`، لكن عبر مسارين مختلفين.

`prisma.config.ts` يستخدم `process.env.DATABASE_URL ?? ""` بدل المساعد
`env()` عمدًا: `env()` يرمي خطأً إذا كان المتغيّر مفقودًا، وكل أوامر Prisma
تحمّل هذا الملف — بما فيها `prisma generate` ضمن `postinstall`. هكذا ينجح
`npm install` حتى في بيئة CI بلا `.env`.

## المصادقة

Auth.js v5 مع Credentials وجلسات JWT تحمل الدور.

الملفات:

- `src/auth.config.ts` — الإعدادات الصالحة لبيئة Edge (بلا Prisma)، تُستخدم في
  `middleware.ts`. تحتوي `trustHost: true` وهي **ضرورية** عند الاستضافة
  الذاتية خارج Vercel، وإلا يرفض Auth.js كل الطلبات بخطأ `UntrustedHost`.
- `src/auth.ts` — الإعداد الكامل مع مزوّد Credentials وقراءة قاعدة البيانات.
  يعمل على Node لأن Prisma لا يعمل على Edge.
- `src/middleware.ts` — يحوّل غير المسجّلين إلى `/login?next=...` ويمنع
  المسجّلين من فتح صفحة الدخول.
- `src/types/next-auth.d.ts` — توسعة أنواع الجلسة بـ `role` و`username`.
  لاحظ أن توسعة JWT تستهدف `@auth/core/jwt` لا `next-auth/jwt`.

ملاحظات أمنية مطبّقة:

- كلمات المرور بـ bcrypt بمعامل تكلفة 12 — لا تُخزَّن كلمة المرور الأصلية
- المقارنة تُنفَّذ دائمًا حتى لو لم يوجد المستخدم، حتى لا يكشف زمن الاستجابة
  أي أسماء المستخدمين موجودة
- الحساب المعطّل يُميَّز برسالة مستقلة عن بيانات الدخول الخاطئة
- التحقق من الجلسة يتم في `middleware` و في تخطيط `(app)` على الخادم معًا
